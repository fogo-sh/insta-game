Method and limits

Hosts: T4g micro / small / medium, Canada Central, two vCPUs, Unlimited credit mode. A .q2 host label identifies the fresh small-host Quake II rerun. Engine, map, configuration, exact timing, workload, and observed player counts are retained in each run’s metadata in DuckDB. Engine-only runs normally warm for 20 seconds and measure 60 seconds; longer runs are explicitly recorded. Network probes originate on the operator’s Linux system.

Defaults target 25% CPU and 20% memory headroom. Query failure rate ≤1% and p95 ≤150ms are screening thresholds, not a published game SLO. FrikBots are QuakeC entities, so their population is verified from distinct join logs; ordinary Quake player queries count network clients. Earlier shared-Wine-display runs are retained but excluded from active-input recommendations. Synthetic clients request 30 FPS where supported; achieved frame rates were not instrumented. Local generator counters are retained separately from EC2 counters. The largest passing tested count is a lower bound when no failing boundary was reached. Persistent RAM and CPU are separate budgets; one universal weight can hide those differences.

Base prices exclude discounts/free tiers, public IPv4, retained EBS, and traffic. Host TX includes telemetry and probes as well as game traffic; bandwidth is a separate cost from CPU and RAM. Modeled surplus is max(0, average cores − baseline cores) × $0.04/core-hour; actual charging depends on credit history. See AWS credit baselines and pricing.
